## 对横评的修正

| 横评主张 | 来源核验与结论 |
|---|---|
| 前三者是提示词技能，第四者有工程管线 | 形态区分大体成立，但不能据此排出效果名次；提示词也可以指导篇章编辑，工程化也不自动保证保真或过检。 |
| blader 的 16:0 是人类盲测 | [Issue #229](https://github.com/blader/humanizer/issues/229) 明确评判者均为同一模型家族的语言模型；这是小样本的模型偏好测试，不能写成人类盲测。README 的“不以通过检测器为目标”有依据。 |
| Humanizer-zh 针对 20 种问题 | [当前 SKILL](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md) 与本地已绑定版本采用 31 条检查点；“20 种”不能代表当前版本。规则按语境编辑，既不只删字，也不按词表判断来源。 |
| academic-humanizer 学术校准与证据纪律 | [README](https://github.com/AIScientists-Dev/academic-humanizer) 自述对比团队已录用论文与获资助申请，并人工审查。不是公开统一基准或独立效果认证。“碾压所有收费工具”没有比较证据。 |
| academic-humanizer 绝不改变引用、数字、主张 | [SKILL](https://github.com/AIScientists-Dev/academic-humanizer/blob/main/SKILL.md) 有保真声明，但部分 before/after 增加输入没有的 p 值、数据集和结果；citation-dumping 示例删减引用。只能借鉴原则，不能把示例当作可照搬的保真实现。禁止所有破折号、固定段落数量等偏好也不直接采用。 |
| Lynote 开源完整 SFT/KTO 重写模型及检测闭环 | [数据管线 README](https://github.com/lynote-ai/humanize-text/blob/main/training-data-pipeline/README.md) 明确只发布数据构建代码、策略及每阶段 50 条演示，不含完整数据、权重、训练启动器、推理服务或 GPTZero 集成。旧回译链与商业版检测反馈能力须分别判断。 |
| 商业版过检率高 30%、质量高 50% | [项目 README](https://github.com/lynote-ai/humanize-text/blob/main/README.md) 说的是相对旧开源链的约略相对增益，是项目自述，不是提高 30 个百分点，也不是四个项目的共同测试。该页旧版 50 对文本质量评分不覆盖当前训练方法或商业版。 |
| Prompt 不能改变统计指纹，回译能根本打碎，因此只有 Lynote 有效 | 已核验材料没有支持这种普遍结论。两者都会改变输出文本；由实现形态无法推出某检测器的泛化结果。不能将困惑度、突发性、篇章结构混为一个统一检测机制。 |
| 回译不可避免失真，之后精修就是最优组合 | 术语和细微关系漂移是需核验的风险，不是每次必然发生；后续精修也不能保证恢复已丢失的信息。没有统一语料、版本、检测器及保真评估支持“最优”。科研稿件不默认采用该链。 |

上述网页是核验时的上游版本；本机上游绑定仍是既有固定提交，未自动更新。未以宣传、stars、演示视频或模型自评作为本地效果证据。

## 本地修改

- 英文 humanizer：取消上下文未判断就改写、新增作者反应及一律禁用破折号的冲突；保留学术范围符号、规范表达与技术术语。
- 两项 humanizer：补充证据具体化条件、引用与主张关联、纯润色不裁决科学强度、论文与计划区别、篇章功能和可选作者样例。
- Research Agent：显式去 AI 味请求按语言选择一个适配器；普通学术润色继续由 nature-polishing 承担，不增加固定多轮链。
- 默认保留稿件原文件，交付 clean final，缺失证据及实质主张修订建议放正文之外。

## 验证边界

本次维护采用受影响的技能/包结构校验、Harness 路由结构校验、差异检查及源/实际安装一致性核对；实际命令与结果写入本地 completion_report。未开展新的模型基准、独立盲测、检测器上传或收费 API 调用。因此只确认规则修订与安装同步，不声称已证明自然度提升、误改率下降或检测器通过率改善。后续在作者授权的真实稿件任务中，以原文对照和作者反馈观察效果。
