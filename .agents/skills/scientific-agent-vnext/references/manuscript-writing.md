# 论文写作：问题、结果和整稿一致性

开始时恢复作者已经确认的研究问题、当前数据结果、研究设计与文章类型。要写的是研究论文、系统综述、范围综述、观点文章还是学位论文章节，决定论证方式。若目标期刊未定，可以先按本学科与文章类型写作，不能宣称已达到某期刊的特定要求。

## 先判断研究能够承诺什么

用一段内部工作说明概括：论文解决哪个可明确表述的问题；已有证据支持到什么范围；当前结果改变了哪一项认识；最强替代解释是什么。作者主线值得尊重，也需要检查其证据基础。若主线与结果冲突，给出具体冲突，不能照写，也不能擅自换题。

对研究刚性边界建立最小认识：对象、统计单位、时空尺度、比较对象、主要指标、分析集合、结果版本、因果强度、验证方式。可从已有文件读出就不再要求作者填写。

## 学术参照

使用作者认可的历史正文作为可用性锚点。需要期刊校准时，选择同学科、同文章类型、主题接近且来源可核查的真实论文。观察它们如何提出问题、比较最近工作、表达限制和组织图文证据。不要复制句子，也不要默认高影响期刊的所有文章都采用相同叙事。

环境科学中的观测关联、模型情景、空间统计和证据综合各有推断边界。不能把所有题目写成“现有算法不足，我们提出新框架并达到更高性能”。必要时读取 domain-and-examples.md。

## 写前的轻量结构

当文章实质结构需要重建时，形成一个临时段落计划：每段的主要句意、证据、需要解释的联系、对下一段的问题推进。成熟提纲已经足够时直接复用。作者要求正文时，无需先让作者逐段批准这些内部草表。

结构与已有证据冲突时，修改结构或明确新的研究建议。不要通过偷偷修改样本、删去反例或重定义结果来适应结构。

## 各章节的工作目标

引言让一个具体研究问题自然成立。背景仅保留理解该问题所需的信息。比较最近工作时准确承认已经解决的部分，再说明当前研究的区别及其科学后果。研究目的必须能被实际设计回答。

方法描述真实执行的设计及分析流程。拟实施步骤留在计划或待办中，不能写成已完成。临时文件名、分类器内部术语和代理工作记录不自动成为可发表方法细节。

结果以实际发现组织，保留单位、分母、不确定性和比较条件。清楚区分研究范围内的测量结果、总体推断和模拟情景。分析过程和脚本运行成功通常不构成科学发现。

讨论围绕少数重要发现解释：它在何种条件下成立，与既有知识有何对应或冲突，哪些机制得到支持，哪些属于合理推测，限制会怎样改变可用结论。不要逐句重复结果，也不要每段机械附上未来研究建议。

摘要和结论最后回查全稿。不能在摘要里新增正文没有证明的机制、数值或政策效果。强结论必须有相应设计和结果支撑；稳健的描述性发现也有价值，不强迫每篇论文宣称范式改变。

## 写作执行

采用完整连贯自然段。正式而具体，解释展开达到作者所需篇幅。段落开头直接承担科学任务，少用空泛重要性宣言。论证应由证据关系推进，避免“首先、其次、最后”替代实质联系。

相关 ARS 文件作为方法来源时完整读取所需内容。不要把上游示例中的教育或工程领域叙事直接套入当前学科。逐章完成后检查引言承诺、结果回答与讨论贡献是否一致。

## 输出

交付请求范围内完整正文。将尚需作者作科学决定的内容从正式论断中分离；稿件带有局部待核查内容时明确它仍是审阅稿。说明实质改动与尚未完成的核查，避免用模型自评分宣布投稿就绪。
