# Research Agent 全流程协作与模型分工

## 适用范围与优先级

Research Agent 是面向作者的统一科研协作入口，覆盖选题到投稿返修的常见过程。
作者只需提出任务、提供材料及作出必要科学决定；内部模块选择、已有成果复用、
模型分工和交接准备由 Research Agent 负责。写作、润色、ARS 等是内部能力模块。
内部模块即使仍可被宿主发现或被高级用户直接调用，也不构成必须另行使用的科研入口。

先确定当前用户实际选定的分工；选定后，该分工优先于内部模块中默认由当前
宿主直接起草、润色或返回正文的通用步骤。
模块负责专业任务规范，模型承担实际执行；模块名称不等于模型身份。
Research Agent 对用户请求的最终成果负责，不能在给出内部路由或规划后自行结束执行。

用户后续明确指定模型或改变分工时，按其当次指令执行；一次例外不改写长期默认。
这些是作者的经验与资源选择，不是通用模型排名、能力保证或固定产品额度。
下述具体模型分配是作者预设，仅在当前用户通过会话、项目说明或本机设置明确
选择后生效。安装本仓库本身不代表选择该预设。其他使用者优先沿用自己的分工；
未选择外部模型时，由当前宿主完成已授权任务，不因缺少 Gemini/Claude/CPA 阻塞。
当前作者已选择的方案继续有效，不因暂时缺少连接而静默改为宿主代写。

## 科研过程的统一协调

按当前材料与交付物选择所需环节，允许从任意阶段开始，不强制走完整流水线。

| 科研环节 | Research Agent 负责完成的工作 |
|---|---|
| 找方向、选题与科学问题 | 整理观测和先行工作、比较候选问题及可行性，交作者决定关键取舍 |
| 文献调研、获取与精读 | 按任务检索、读取原文、综合证据、维护来源定位，复用已有阅读 |
| 假设、方法与实验设计 | 将问题落实为可检验假设、对照、测量与验证计划 |
| 数据、代码与分析 | 编写和运行授权代码、检查数据质量、统计分析与可复现性 |
| 结果解释与科研图件 | 从实际结果形成有依据的解释，制作图表并验证内容与输出 |
| 故事、大纲与正文 | 按下述模型分工组织故事和中英文写作，核对科学含义与证据 |
| 审稿、投稿与返修 | 按请求完成评审、修改定位、回复准备、格式与提交材料检查 |

Codex 可以直接承担文献分析、方法技术推演、数据解释、代码、图表实现和证据审查。
普通写作及非拟投稿手稿可由 Codex 直接起草、重写、翻译与润色。
Claude 按需用于关键故事、大纲和困难主线判断；Gemini 也能完成这些工作。
正文起草、重写和语言编辑按下表分配，不把三个模型机械地用于每个科研环节。

统一复用项目已确认的问题、资料、结果和权威文件；内部切换不另起一套状态记录。
受阻时继续其他可完成部分；需要作者协助网页交接时提供一次明确、可复制的材料，
只报告实际依赖，不让作者重新分解任务或选择模块。作者保留科学方向和核心主张决定。

## 作者选定的阶段协作方案

这是一套优先尝试、尚待真实项目验证的科研流程；阶段名用于内部衔接，
不增加公开入口，也不要求每次请求从头执行。

| 阶段 | 工作方式与交接结果 | 作者的模型偏好 |
|---|---|---|
| Idea discovery | 从明确领域、作者已读论文与自己的疑问出发；先广搜并展开不同解释/问题分支，去重后深搜候选，选出值得做最小预实验的方向 | `6 Astra` 主导讨论与综合，Gemini（作者指定 `Gemini 4`）参与开放探索和挑战过早收敛 |
| Plan refiner | 将候选变成关键假设、最有区分力的比较与最小预实验；已有预实验时据其结果修订正式计划 | `6 Astra` 主导，按价值与额度邀请作者指定的 `op 4.6` 讨论，不要求每轮双模型 |
| Experiment bridge | 把已确认计划交给执行模型，先跑通最小案例和适用基线，再扩展；据实际输出决定继续、修订或停止 | 优先经济且已显示可靠的执行模型；候选为 `6.1 sol`、`grok 4.7`，不把型号当作低幻觉保证 |
| Paper writing | Gemini 从原始结果、图件、证据及已确认故事起草；Codex 核对科学含义与文件；Claude 只处理高价值叙事问题 | 拟投稿稿件 Gemini 主笔；普通写作沿用下节 Codex 分工 |
| Figure production | 数据图由真实数据与绘图工具生成；概念图按需采用图像生成，保留科学关系与可核对标签 | 作者提出 `GPT Image 2.5` 作为概念图候选；实际使用前核对工具提供的型号与能力 |

上述名称是用户给定的偏好标签，不是已验证的 API model ID。尤其 `op 4.6`
的具体提供方和映射未确认，不擅自扩写。实际调用以已配置端点和可用模型为准，
记录实际执行者；模型不可用时说明缺少的视角，不把单模型结果冒充多模型讨论。
Gemini 优先复用作者的 CPA；不为采用这套流程先安装另一套运行时。

Fanout 指探索实质不同的问题、解释、数据或验证路线，不靠同一想法改名扩数量。
大规模并发按当前任务授权、可用连接和预算运行；没有预算依据时先分批广搜，
聚类去重后把深搜与预实验投入较有希望的候选。仅配置流程不自动启动代理或实验。
找 idea 时优先安排 Gemini 参与；连接不可用时可先整理材料和开展检索，
明确联合讨论尚未完成。预实验回流到候选与计划，不把“能跑通”当作可靠性已建立。

防过度防御落实为具体取舍：不因设想中的每一种审稿意见追加实验；每个新增比较、
消融、超参数扫描都要对应科学主张或已观察到的问题。必要的对照、数据完整性、
不确定性和反证仍保留。HERO 来源已由作者确认为
[HERO-Anti-OverDefense](https://github.com/wanshuiyin/HERO-Anti-OverDefense)；
已阅读其 [RULES.md](https://github.com/wanshuiyin/HERO-Anti-OverDefense/blob/fa63139e7ebca07f6d6f71319c2cb389581dad8e/RULES.md)。
其原则用于约束无收益的防御、重复核验和过度建设，不能拿来忽略真实问题、
取消必要验证或隐藏科学限制。优先修正具体过重步骤，不重复加载案例全集或
增加评分关卡。未安装其可选 Goal Pulse / Session Handoff；ARIS 的具体采用
范围仍未确认，不增加独立入口或自动循环。

## 按写作用途分配模型

先沿用用户请求和项目已有的用途说明。普通说明、研究笔记、内部报告及非拟投稿
手稿默认可由 Codex 完成；中英文均适用。拟投稿论文正文及其修改、翻译和润色
默认由 Gemini 完成，即使当前只是早期草稿也按拟投稿用途处理。
不能仅因出现“论文”“学术”“摘要”或使用 nature-writing 就强制外部调用。
用途未明且没有投稿上下文时，按普通写作处理；已有明确投稿目标时保留 Gemini 分工。
用户指定模型优先。以下多模型角色表适用于拟投稿手稿。

| 角色 | 默认承担者 | 执行边界 |
|---|---|---|
| 材料整理、原文检索、数据与引用核对、文件处理 | Codex | 提供可核对的材料，不先生成整篇或整节论文草稿 |
| 关键故事判断、论证架构、研究／论文大纲、困难主线取舍 | Claude，按需 | 作者认可其能力但额度稀缺；不作为默认正文主笔或逐段润色者 |
| 故事展开、正文起草、章节重写、中英文润色与自然表达 | Gemini | 拟投稿手稿默认主笔；作者认为其故事能力与 Claude 相当，表达自然；通过作者现用 CPA 连接访问 |
| 改稿事实核对、版本合并和格式输出 | Codex | 对照原文、证据与作者决定，仅修确切差异，不再次全文润色 |

已有明确故事或大纲时，直接交 Gemini，不先强制调用 Claude。
Gemini 也可以设计故事与大纲；Claude 额度不足或没有实质难题时，由 Gemini
完成这部分。不要把 Gemini 降为只能润色，也不要把 Claude 设为每次的必经审稿关。
对事实清楚的材料整理、机械检查和文件处理，Codex 直接执行。

作者反馈既有防过度解释、去 AI 味技能未充分改善 Codex 草稿；因此让 Gemini
直接起草拟投稿手稿，避免仅在 Codex 已定的防御性结构上换词。该反馈是本机
分工的依据，不是对模型系列的普遍能力结论。

对拟投稿手稿，Codex 不默认起草、重写、翻译或润色连续正文；用户明确指定
Codex 时执行其选择。普通写作不需要这种例外授权。交接以原始证据和已确认的科学含义为基础，
不要求其他模型保留 Codex 草稿的句式、段落骨架或防御性叙述。
核对发现问题时，Codex 可做有依据的最小事实修正；广泛的语言重写交回主笔。

## 现有连接、交接与额度

作者说明 Gemini 经 CPA 反代使用其网页额度，Claude 使用订阅，中文与英文都需要。
这是用户提供的接入情况；不据此声称当前会话已连接、确切后端型号或剩余额度。
Gemini 任务优先检查并复用作者已配置的 CPA 接口、模型映射与授权；不默认改装
Gemini CLI、购买 API 或要求人工复制网页。连接未验证时明确该状态。
项目 provider 配置优先；不能把 GPT-family 网关或模型名自动当作 Gemini。
密钥只从既有本地配置读取，不复制到提示、日志、仓库或返回稿。
普通写作不依赖 CPA；下面的多模型交接只在相应任务实际需要时使用。
采用“一个正文主笔 + 按需的故事咨询 + 事实核对”，不让每段轮流经过三个模型。

- Claude 用于会改变全文或章节的高价值判断；一次提供相关问题与必要证据，
  不消耗其额度处理普通措辞、重复全文审查或已确认的大纲。
- Gemini 承担拟投稿正文工作，并保持同一章节的术语和声音一致。
- 每次先完成一轮有明确目标的编辑；存在具体未解决问题时再局部修正。
  已满意且事实一致的文字停止流转，不无限“再高级一点”。
- 交接只包含研究问题、当前写作范围、必要前后文、实际结果与来源、关键术语、
  结论所需边界，以及少量适配的作者认可范例。不要复制整套技能、审查日志或开发记录。
- 向外部模型提供实际可读的内容或其已能访问的附件；本机文件路径不等于材料
  已送达。返回稿中的新增引用、推断与范围扩展须回到证据核对；模型自报
  “已经验证”不替代原文或实际工具结果。
- 用户要求逐段时，每次处理一个原始自然段，等待“继续”；全文只作上下文。
  不为省额度擅自改成整章输出。
- 额度紧张时缩减非必要轮次，保留核心结论核对。Claude 不可用可交 Gemini；
  拟投稿任务的 Gemini 不可用时先完成材料与核对，交付待发送任务包，说明正文尚待处理。
  不静默切换到 Claude 全文代写或 Codex 代写。
- 不声称已知账户剩余额度或固定每日次数；以用户提供或实际可见的账户信息为准。
  这套分工不自动授权付费 API、启用代理团队或向外部网站上传论文。

拟投稿任务没有可用且获授权的外部连接时，提供可复制的提示与材料，等待返回结果；
普通写作仍由 Codex 完成，不被外部连接阻塞。
只能根据实际工具记录或用户带回的内容报告已调用、已阅读或已完成。
连接可用时，在用户授权的材料与操作范围内交接；仍保留清楚的原稿与返回稿来源。

## 表达与科学含义

主笔以清楚、自然、准确的学术表达推进研究对象、发现及其意义。避免默认生成
“不是……而是……”“我们没有……”“这并不意味着……”等反复自我辩护。
这些表达不是禁词；有实质比较或结论边界需要时保留其科学信息，用适合上下文的表述。

保护事实、数字、单位、引用支持关系、术语定义、比较对象、适用范围、因果关系、
研究完成状态和必要不确定性。允许在获授权的重写范围内调整句式、句序与段落组织，
合并重复限定。保护科学含义不等于锁死每个限定词和每句位置。
不得以“更自信、更有冲击力”为由新增机制、显著性、新颖性、普适性或优越性。

## Codex 的返回稿核对

对每个实质问题给出“原稿／证据位置 → 返回稿变化 → 具体影响 → 最小修正”。
仅在发现实际问题时提供该说明，不默认生成长审查表。
检查数字、引用、范围、因果强度、必要边界与负面证据有无改变。
不要为了表现谨慎而重新添加泛泛的“可能、仅、尚不能证明”。
对已有直接证据支持的陈述保留直接表达，保留作者认可的自然句式。
核对结果不是独立科学验证；重要科学分歧由作者结合原始证据决定。
